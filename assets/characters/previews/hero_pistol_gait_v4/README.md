# 권총 보행 D · 조사 기법 적용 (2026-11-24)

최신 우선: [FACE-R1 얼굴 공유](identity/README.md). D가 C 상태/새 보행 원화를 섞으며 얼굴 크기가 달랐던 문제를 같은 머리 레이어 공유로 고쳤다. 화면 `BUILD FACE-R1 · D 얼굴 공유`로 최신 실행을 구분한다. 아래 원본 상태/보행 원화는 기록이며 실제 D 로더는 identity 자산을 사용한다.

최신 후속: 사용자는 D 동작 개선을 좋게 평가하고 3번째의 높은 무릎과 약한 쥬시를 요청했다. [낮은 통과 자세/접지 반응](refinement/README.md)을 D 기본에 적용했다. F10으로 이번 수정 전/후 비교. 아래 원본8키/기록은 보존한다.

## 사용한 기존 조사

[보행 적용 계획](../../../../docs/plans/2026-11-24_보행기법_적용.md)의 기존 문서/1차 출처 대조를 먼저 따른다. 핵심 자세, 모형 선검수, 같은 보행 원형의 팔 변형, 이동/공격 상태 분리, 거리와 보폭 연결을 적용했다. 공격용 스미어/히트스톱으로 발 오류를 가리지 않는다.

## 실제 제작

- 원본 `busan_hero.blend`는 읽기 전용으로 열어 Walking.fbx의 8시점 실제 관절만 추출했다: `pose_joints.json`, `pose_guide.png`. 카메라 투영과 리타깃 자체에 비대칭이 있어 이 결과를 완벽한 발 접지로 취급하지 않았다.
- 그 검토 후 접촉/통과를 명시한 별도 설계 IK 안내를 만들었다: `designed_contacts.json`, `contact_guide.png`. 이것은 실제 캡처 관절과 구분되는 **자세 안내용 모형**이며 최종 캐릭터 원화가 아니다.
- built-in image_gen으로 승인 외형에 적용했다. 첫 8장 `rejected_repeated_walk.png`는 같은 네 단계 반복으로 반려. 다음 `aimwalk_candidate.png`는 반대 발 접촉은 구분됐으나 2/3/5번 다리 정체성이 틀려 해당 프레임을 지정 수정했다. 최종 `generated_aimwalk.png`의 다리 순서를 보존하며 팔만 낮춘 `generated_walk.png`를 생성했다. 각 요청은 `prompts.json`.
- 최종 원화는 전신 8장씩이다. 게임 캐릭터를 코드로 그리거나 36px 팔다리를 회전시키지 않았다. 시트 자르기/알파 정리/공통 배율 샘플링으로 64px 칸, 기준 몸 높이36px로 정리했다. 프레임마다 bbox 높이나 바닥을 따로 맞추지 않았다. 두 시트는 같은 보행 순서지만 생성 픽셀이 완전히 동일한 하체는 아니다.
- `gait_meta.json`의 발 표시로 반 주기의 후방 이동량을 추정했다. 양발 평균14.5native px를 반 주기 이동으로 보고 한 주기29native px / DOT =48.9375world 단위를 적용한다. 조준도 같은 보폭 원형이며 게임의 느린 조준 이동에 맞춰 재생이 느려진다. 다른 보폭40을 임의 적용하지 않는다.

## 게임 적용과 비교

- `tools/권총_보행개선_플레이.cmd` 실행 → D 시작. WASD 이동, 좌클릭 유지 조준/떼기 발사, F8 A→B→C→D, F9 적 정지/재개, R 초기화, Esc 종료. 기존 실행 중인 창은 이전 코드를 메모리에 갖고 있으므로 이 런처로 새 실행한다.
- C의 기존 4키 원화와 공격 시 이동 정지는 보존했다. D는 8키, 실제 이동거리 기반 위상, 이동 중 발사해도 전신 반동 한 장으로 다리를 덮지 않는다.
- `Hero.walk_while_shooting`은 기본 False이며 D에서만 True다. 기존 근접공격 경로가 권총 발사 때도 이동을 막던 문제를 D에서만 해제했다. 조준 속도로 입력 이동을 처리하고 사격 시간/명중/탄약은 유지한다. 따라서 C/D는 외형만 다른 완전 동일 동작 비교는 아니다.
- D 이동 중 전용 상체 반동 원화는 아직 없다. 다리는 계속 재생하고 기존 총구 불꽃/트레이서/화면 반응으로 발사를 표현한다. 정지 반동/피격/쓰러짐/정지 A형 조준은 C 상태 키를 재사용한다. 기존 명중 히트스톱은 세계 전체에 그대로 적용되며 이 순간의 전체 정지는 별도 현상이다.

## 검수와 남은 문제

- `tools/checks/check_pistol_gait.py`: 실제 60Hz 게임에서 보행/조준 8키, 이동 사격 실명중·탄차감·하체 표시 유지, 정지/이동 차단/정지 시계, 반대쪽 조준 이동, A/B/C/D 위치·체력·탄약 유지, 초기화 검사. 결과 `runtime_check.json`.
- 보존 C의 상태/발사/피격/사망/초기화 회귀 검사도 통과했다: `tools/checks/check_pistol_flow.py`.
- 원화 시각 검수: `frame_board.png`, `aim_native_board.png`, `feet_grid.png`. 게임 검수: `game_comparison.gif`, `game_review_board.png`(C/D 실제 화면, 같은 입력 시퀀스; 이동 사격 처리 차이 포함).
- 수동 추정 부츠 중심의 **같은 프레임 유지 중 최대 이동**: C6.519 → D3.259native px. 이 숫자만으로 접지 완료/자연스러움 보장을 하지 않는다. D의 **후보 지지 구간 전체 부츠 중심 범위**는7.654native px로 남아 있다. 자료는 `foot_audit.json`. 발바닥 중심은 뒤꿈치→발끝 구름 중 같은 접점이 아니며 좌표 표시도 근사다.
- 시각상 반대 발 접촉/통과와 이동 사격의 다리 흐름은 구분되지만, 발 내밀기/착지 사이 간격과 골반 체중 이동은 더 다듬을 여지가 있다. 강제 포즈 제어·완전한 발 IK로 보고하지 않는다. 좌우 반전만이며 전용 후진/상하 원화, 구르기/줍기, 최종 몸/총 분리는 미완성이다.
