# 붉은 재킷 주인공 · 외형 확인 2장

> 최신: 사용자 승인 후 걷기 6자세와 검 베기 3자세를 추가했다. 기존 시험 실행 파일은 새 모션을 사용한다. [현재 모션과 플레이 설명](../hero_redjacket_motion_v1/README.md)을 먼저 본다. 아래는 두 자세만 있던 이전 단계의 기록이다.

## 후속 · 직접 플레이

사용자 요청에 따라 `tools/새_주인공_플레이.cmd` 또는 `.venv\Scripts\python.exe tools\run_redjacket_trial.py`로 새 외형을 조작할 수 있게 연결했다. 기본 스테이지에서 기존 이동/전투/피격 판정을 사용한다. `--spitter`를 추가하면 원거리 피폭체 시험장이다.

- WASD 이동, 좌클릭 누르기/놓기 준비/공격, Space 회피, R 재시작, Esc 종료.
- 기존 기본 무기 수치를 유지하며 검 이름과 외형으로 시험한다. 검이 그림에 포함되어 있어 다른 무기 줍기는 이번 실행에서 제외한다.
- 대기/이동은 대기 그림, 준비/공격은 준비 그림을 임시 사용한다. 베기/걷기/피격/쓰러짐의 실제 중간 그림과 위아래 방향은 미완성이다. 회피는 기존 잔상 방식이다. 현재는 미끄러지듯 움직이고 검이 실제 궤적을 따라 휘둘러지지 않으므로 완성 동작으로 평가하지 않는다.
- 기존 게임 기본 실행과 자산은 보존하고 별도 launcher에서 외형만 연결한다. 재시작에도 새 외형이 유지된다.
- 숨김 실제 게임 창에서 이동·준비·공격·회피·재시작 렌더 검사를 통과했다. 아래의 미연결 기록은 플레이 연결 전 외형 제작 단계의 기록이다.

2026-11-23. 사용자 선택은 세 번째 시안(검은 머리, 붉은 재킷, 넓은 바지, 양손 검). 최신 요청에 따라 작은 부분만 확인하며 나머지는 사용자 검토 후 진행한다.

- 기준 원화: `../../concepts/hero_redesign_v1/hero_three_designs.png`의 오른쪽 인물과 아래 작은 도트.
- 내장 image_gen으로 외형 확인용 한 방향 대기/검 준비 두 장 생성. 원본 `generated_poses.png`, 요청 `prompt.txt`.
- `idle_36px.png`, `guard_36px.png`: 64×64 RGBA. 대기 몸 높이를 36px로 맞춘 하나의 배율을 두 자세에 공통 적용. 고정 발 기준점 (32,58). 준비 자세는 고개가 낮아지고 검끝이 머리 위로 올라오므로 전체 bbox 높이와 몸 높이가 다르다. 프레임마다 몸을 다른 배율로 늘리지 않았다.
- 검이 그림에 포함된 외형 검토 키 이미지다. 무기 분리/손 좌표/3D 모델/리깅/애니메이션/이동/피격/전투 적용은 이번 범위가 아니다. 두 장을 이어 붙여 완성 애니메이션이라고 보지 않는다.
- `comparison.png`: 위는 도트 정수 5배 확대, 아래는 실제 게임 렌더 캡처(기존/새 대기/새 준비). `game_existing.png`, `game_idle.png`, `game_guard.png`는 전체 화면이다. 캡처 프로세스에서만 draw를 바꿨으며 기존 자산과 게임 기본 주인공은 교체하지 않았다.
- 확인: 두 결과 모두 가장자리 접촉 없음, 같은 바닥 행 58, 같은 축소 배율. 숨김 pico2d 창에서 두 자세와 기존 캐릭터를 각각 실제 렌더했다.
- 관찰: 기존의 곧은 가는 체형과 달리 하체 폭과 무게중심이 구분된다. 준비 자세에서는 칼과 팔의 방향도 다르게 읽힌다. 36px에서는 원화의 얼굴/팔 근육/붕대 세부가 많이 사라지고 게임의 어두운 보정에서 재킷이 탁해진다. 원화와 완전 동일하거나 동작 간 해부학 일관성이 검증되었다고 주장하지 않는다.
- 다음은 사용자 외형 확인이다. 승인된 방향에서 실루엣·팔레트를 고정하고 기준 3D 제작과 후속 동작으로 넘어간다. 이번 생성 그림을 전체 제작 파이프라인 확정으로 해석하지 않는다.
