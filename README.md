# 부산까지 (가제)

핵 재난 이후 가상의 한국에서 서울부터 부산의 대피 거점까지 가는 다크풍 2D 도트 게임. 피폭체를 한 방에 베는 짧은 실시간 칼싸움을 반복하고, 살아남으려 시간을 느리게 하는 힘을 쓸수록 피폭 수치가 올라 괴물이 되어 간다.

- 개발 환경: Python + pico2d
- 화면: **탑뷰**(위에서 비스듬히 본 3/4 시점), 싱글 플레이 ([기획 고정 문서](docs/planning/DESIGN_LOCK.md), [PRD](PRD.md) v4.3~)
- 현재 상태: **탑뷰 전투 한 구역.** 마우스 방향 한 방 베기, 구르기, 시간 느리게와 피폭 수치, 바라보는 방향 시야(폐차가 가림), 보고 듣고 찾는 피폭체(좀보이드 규칙 참고).

## 실행

Windows에서 Python 3.12로 검증했습니다. 저장소 루트에서 다음 명령을 실행합니다.

```powershell
python -m pip install -r requirements.txt
python src/main.py
```

## 조작과 규칙

- `WASD` 사방 이동, `좌클릭` 마우스 쪽으로 짧게 파고들며 한 번 베기(피폭체는 한 방), `Space` 구르기(무적, 붙잡혔을 때 빠져나감)
- `우클릭`을 누르는 동안 시간이 느려지고 **피폭 수치**가 오릅니다. 100%면 강제로 풀립니다.
- 주인공 체력 2칸, 쓰러지면 그 구역을 바로 다시 시작합니다. `R` 다시 시작, `Esc` 끝내기.
- **시야:** 마우스 쪽 원뿔과 몸 주변만 보이고, 폐차 뒤는 가려집니다. 어둠 속 피폭체는 보이지 않습니다.
- **피폭체:** 앞을 보거나 소리(발소리 < 구르기 < 베기)를 들어야 쫓아오고, 놓치면 마지막 위치로 가다 잊습니다(`?`). 소리를 들으면 먼저 돌아보고, 본 지 0.5초가 지나야 공격합니다(그 전엔 팔을 든 채 멈칫). 머리 위 `!`가 뜨면 곧 공격이 오고, 내 시야 밖에서 붙은 공격은 예고가 짧습니다. 두 마리 이상 붙은 채 맞으면 잠깐 붙잡혀 구르기로만 빠져나갑니다.
- **사방에서 몰려옴:** 구역 가장자리의 골목·문(어두운 틈)에서 피폭체가 계속 들어옵니다. 베거나 구르는 소리가 나면 더 빨리, 그 소리 쪽으로 옵니다. 화면 위 "남은 피폭체"가 0이 되면 구역 정리입니다.
- **소리:** 시야 밖 피폭체도 그르렁·발소리·예고음이 거리만큼 들립니다.
- `F2` 피폭체 감각을 끄고 예전 규칙(가까우면 무조건 쫓아옴)과 비교합니다.

예전 2.5D 거리 게임과 횡스크롤·탑뷰 시험판은 [src/legacy](src/legacy/README.md)에 보관돼 있습니다.

## 게임의 흐름

핵전쟁 오프닝 → 대피 튜토리얼 → 방공호에서 준비 → 지상·건물 탐색 → 전투·생존자 조우 판단 → 다음 거점 도착 → 정비 → 부산 도착.

첫 방공호에서 공용 물자를 수집하고 생존자와 물물교환한 뒤 출발합니다. 대화나 개인 물자에 대한 행동에 따라 생존자의 관계가 바뀝니다. 생존자 발밑에 관계를 원으로 표시합니다. 미확인은 회색 원과 `?`, 우호는 초록 원, 적대는 빨간 원입니다. 첫 조우는 미확인이며, 대화와 행동을 통해 태도가 드러나면 발밑 표시가 바뀝니다. 대화와 물물교환은 미확인 또는 우호 상태에서만 가능합니다.

## 코드 구조

수업(LEC11~14)에서 배운 구조를 따릅니다. 화면에 나오는 것은 모두 `update()`와 `draw()`를 가진 클래스이고, `game_world`의 레이어에 담아 한꺼번에 갱신하고 그립니다.

| 파일 | 역할 |
| --- | --- |
| `main.py` | `reset_world → handle_events → update_world → render_world` 루프와 객체 사이의 규칙(줍기, 출구, 전투 시작·종료) |
| `game_world.py` | 레이어별 `add_object` / `remove_object` / `update` / `render` (배경 → 바닥 표시 → 캐릭터(깊이 정렬) → 효과 → 전투 표시 → 상단 띠 → 팝업 → 하단 핫바) |
| `player.py`, `zombie.py` | 주인공과 피폭체. `transitions.Machine` 상태 기계(주인공: IDLE·WALK·SNEAK·DASH·PICKUP·SWING·COMBAT) |
| `background.py`, `wreck.py`, `exit_door.py`, `effects.py` | 배경, 폐차, 출구, 타격 효과 |
| `hud.py` | 탐색 중 상단 띠, 하단 띠, 배낭·설정 창 |
| `combat.py` | 턴제 전투 규칙(선공, 턴 자원, 이동, 명중·피해 굴림, 기회 공격, 적 행동) |
| `combat_view.py` | 전투 화면 요소별 클래스(이동 영역, 명중 돌림판, 대상 위 명중·빗나감과 피해 숫자, 대상 정보, 턴 순서, 핫바, 전투 기록 등) |
| `hit_feel.py`, `screen_shake.py` | 모든 공격에 공통인 타격감(피해 비율 → 약·중·강 단계, 히트스톱·숫자 크기)과 화면 흔들림 |
| `nav.py` | 보이지 않는 0.25m 격자의 길찾기와 거리(미터) 계산 |
| `ui.py`, `camera.py`, `game_clock.py` | 공통 색·글꼴·도형, 카메라, 프레임 시간 |

## 개발 원칙

리소스는 프로젝트 기준 상대경로로 로딩합니다. 실제 기능 구현과 검증 단위로 커밋하며, 완성된 작업을 사후에 나누거나 빈 커밋으로 개발 기록을 만들지 않습니다. 기획 1 ‘도장깨기’는 이 프로젝트에 포함하지 않습니다.

## 현실과 가상의 구분

실제 대응 원칙을 일부 참고하지만, 부산 이동·적 행동·체력 수치는 가상 설정입니다. 실제 비상대응 지침을 대신하지 않습니다. 참고 링크는 PRD와 기획서 발표자 노트에 기록했습니다.
