- **구현:** pico2d 창, 플레이어 이동과 벽 충돌, 방독면 캐릭터와 필터 수집, 거점 출구, 방공호 도트 배경, 걷기 스프라이트, 필터 HUD, 네 방향 줍기·조용히 걷기 애니메이션.

## 2026-11-10 — 타격감, 에셋 방침, 3D 캐릭터 파이프라인
- **결정:** 필터 줍기를 빼고 오염·보호 장비는 추후 개발. 이후 사용자 지시는 PLAN "사용자 지시 기록"에 남긴다.
- 공격 결과를 대상 머리 위에 "명중/빗나감" 글자로 띄운다.
- **공통 타격감 구조:** 피해가 대상 최대 체력에서 차지하는 비율로 약·중·강을 나누고 히트스톱·화면 흔들림·숫자 크기를 키운다. 방망이뿐 아니라 모든 공격에 같은 규칙(`hit_feel.py`, `screen_shake.py`).
- 지상 도로를 약 10m 깊이로 넓히고 바닥 범위를 맵별 값으로 분리.
- 외부 도구·맵 에디터·에셋 조사([외부 도구](research/EXTERNAL_TOOLS.md)). **무료만, 라이선스는 교육용으로 폭넓게, 일단 쓰고 문제가 생기면 교체.** 적은 무료 좀비 스프라이트 + 적대 생존자.
- [1차 발표와 지금의 차이](planning/ORIGINAL_VS_CURRENT.md)를 정리했다(교수님 지침: 처음 기획에서 벗어나지 말 것).
- **캐릭터 파이프라인:** 고품질 도트 제작 방식 조사 → Blender 설치 → 3D 기본 몸(Quaternius, CC0)을 옆모습 도트 시트로 렌더하는 스크립트. 기본 몸 v1 → v2(셀 셰이딩·외곽선) → v3(다리 길이·바닥 맞춤) → v4(카메라를 위에서 내려다보게, 과한 비율 되돌림).
- **문제:** 비율을 과하게 키워 "아래에서 쳐다보는 느낌", "은신 자세 이상함" 지적 → 원인 분석과 [그림 피드백·점검표](../assets/characters/ART_FEEDBACK.md)를 만들어 결과를 보여 주기 전에 매번 통과시키기로 했다.

## 2026-11-11 — 움직임 다듬기와 주인공 모습 찾기
- **은신:** 걷기에 웅크린 자세를 섞는 기능(회전을 올바르게 더하는 COMBINE). Shift만 눌러도 바로 몸을 낮춘다.
- **휘두르기:** 두 번째 무료 동작 팩을 받아 칼 베기 A + 복귀 동작으로. **맞는 칸**을 판정 순간에 맞추는 공용 방식(`look.json`의 `impact`)을 넣고, root 뼈를 고정해 제자리에서 끝나게 했다.
- **이동 속도와 보폭:** 처음엔 다리가 이동보다 3배 느려 발이 미끄러졌다. 다리를 걸은 거리로 재생하도록 바꾸고(`stride_m`), 느림·빠름 의견을 거쳐 보폭 측정 오류(뛰기의 공중 구간을 놓침)를 고친 뒤 걷기 1.7m/s·은신 1.0m/s로 맞췄다. 1/60초마다 발 픽셀을 재서 확인했다.
- **작업 방식:** 작업하면서 리팩터링도 함께(이동 속도 m/s 통일, 숨은 배율 상수 제거, 휘두르기 끝 판정 `swing.done`). 커밋과 GitHub 푸시를 Claude가 관리한다.
- **주인공 모습 찾기(여러 방식 시험):**
  1. 기본 몸에 부위 색칠 + 도형 소품(주인공·간호사·인부) → 노란 마네킹 같다고 폐기.
  2. Gemini 웹으로 **시안**(겨자색 후드 재킷 생존자)을 받고 게임 크기 도트로 정리하는 도구.
  3. 시안 컷아웃 / Blender 다시 칠하기(로토스코핑 A) / 시안 부품 시트를 3D 각도로 조립 비교.
  4. Mixamo(무료 계정)에서 옷이 모델링된 Alex와 동작 7개 → "맘에 안 든다".
  5. 기본 몸과 같은 뼈대의 Quaternius 무료 의상 부품 → "맘에 안 듦".
  - 시안을 한 칸씩 고쳐 그리기용 자세 안내 그림 16장과 문안도 준비했다.
- 주인공은 노란 방호복에서 "생존자 느낌"으로 바꾸는 안도 검토했다(비교 문서에 기록).

## 2026-11-12 — 기본 몸 위에 2D로 옷 그리기
- 사용자: "그냥 여기서 니가 만들어 봐." 3D 옷 대신, 마음에 든다는 **기본 몸의 움직임은 그대로 두고 그 위에 칸마다 2D 도트로 옷을 그리는 도구**(`tools/sprites/paint_clothes.py`)를 만들었다.
- 부위 지도(가까운 쪽·먼 쪽 팔다리 구분)를 보고 시안 색으로 머리카락·겨자색 재킷·바지·부츠·장갑을 칠하고, 시안의 배낭·방망이 도트를 동작 각도대로 붙인다. 지금까지 중 시안에 가장 가깝다.
- 개발일지(이 문서)를 만들었다.
- **게임에 넣기:** "3D는 움직임만 보고 그 동작대로 스프라이트를 만들면 된다"는 방향을 확정. 한 줄 명령(`render_character.py hero_2d:hero`)으로 동작 8종을 그려 게임 주인공을 노란 재킷 생존자로 교체했다. 누운 자세가 통째로 노랗게 칠해지던 문제를 고쳤다.
- **배낭 빼기:** 사용자 의견으로 주인공의 배낭을 없앴다(의상 파일의 `backpack` 설정 하나로 켜고 끔).
- **전투 방식 결정:** 콘텐츠가 적은 2D 게임에서는 BG3식 턴제가 반복적이 될 수 있어 **실시간 근접 전투로 되돌리기로** 했다(1차 발표 기획으로 복귀). 주무기는 방망이 대신 다른 무기를 검토한다.
- **주무기 마체테:** 무기 추천 기준(세계관, 만들 수 있는 동작, 실시간 손맛, 탐색 쓰임, 1차 발표와의 연결)을 정리하고 마체테로 정했다. 무기 그림을 바꿔 끼우는 구조를 만들고 주인공을 마체테로 다시 그렸다.
- **실시간 전투 첫 단계:** 공용 무기 데이터와 근접 공격(`weapon.py`), 마체테 3연타(칼 베기 A·B·C 동작을 2D로 그림), 대시 무적 회피, 피폭체의 체력·피해·쓰러짐, 기습 3배, 피해 숫자. 처음엔 기습이 안 들어갔다: 칼이 닿는 순간 판정해서 그 사이 피폭체가 알아챘기 때문 → 휘두르기를 시작한 순간 들키지 않았으면 기습으로 고침. 자동 점검(연타·피격·회피·기습·처치) 통과.
- **연타 리듬:** 사용자 의견 "1·2타는 빠르게, 3타 때 동작이 크게" + "첫 번째를 마지막으로". 크게 숙였다 올려 베는 동작을 3타로 옮기고 1·2타는 준비 동작을 잘라 빠르게(0.32·0.34초, 피해 2), 3타는 0.66초·피해 6·큰 밀어내기. 마무리 타는 무기 데이터의 `heavy` 표시로 타격감이 한 단계 커진다(공통 규칙). 3타 처음에 서 있는 칸이 멈칫해 보여 숙인 자세부터 시작하게 잘랐다(렌더러가 `동작@4-`처럼 끝을 생략한 구간을 받게 함).
- **검로를 칼 방향대로:** 흰 검로가 늘 같은 모양의 호라서 칼과 따로 놀았다. 옷 그리기 도구가 칸마다 칼 위치를 `blade.json`으로 남기고, 게임은 칼이 실제로 돈 길을 따라 초승달을 그린다. 처음엔 내지르기가 뒤→앞으로 180° 뒤집혀 머리 위로 큰 호가 생겼다 → 한 칸 사이에 너무 크게 돌면 칼끝 뒤 직선 잔상으로. 맞은 뒤 다음 칸으로 넘어가면 검로도 그 동작을 따라간다. 사용자 요청으로 1·2타를 0.4초로 늘렸다.
- **1·2타 순서 교체:** "2타가 잘 안 보인다"는 의견으로 내지르기를 1타, 가로 베기를 2타로. 연타가 직선 잔상 → 머리 위 호 → 큰 올려 베기 순으로 점점 커진다.
- **기획 논의(미확정):** 방사능 변이 능력, 피폭체가 떨어뜨리는 결정 재화로 스킬 강화, 피폭 수치와 억제 주사기, 전투가 지루할 수 있다는 고민에서 총·시야 제한·탑뷰까지 이야기했다. 결론은 "우선 하던 것 계속". PRD 10장 "검토 중인 방향"에 기록.
- **방향 한 장 정리:** 고민을 A(살아남는 긴장감)·B(변이된 몸의 손맛)·C(길 위의 선택)로 묶어 1차 발표와 비교했다. 다시 보니 1차 발표의 화면이 탑뷰였고 총기가 후순위 아이디어였다. 제안은 "A 중심 + B의 완벽 회피 반격 하나, 화면은 탑뷰 시험판으로 비교 후 결정".
- **결정:** 추천(A 중심, 옆 시점 유지, 어둠+손전등 시야) 중 **공기 잔량과 총소리로 적 부르기는 제외**하기로 했다.
- **완벽 회피 → 반격:** 할퀴기 직전 0.2초 안에 대시하면 느린 화면(0.35초, 30% 속도)과 하얀 고리, 1.2초 안의 다음 타격은 피해 2배 반격. 처음엔 대시가 48px나 움직여 공격 판정 순간 이미 사거리 밖이라 "회피"가 거의 안 잡혔다 → 적은 "어디까지 닿는지"만 알려 주고, 공통 규칙(`dodge.py`)이 최근 대시와 거리로 판단하게 했다. 자동 점검에 완벽 회피·반격 추가.
- **1·2타가 보이게:** "1·2타가 너무 빨라 잘 안 보이고 흰 선도 안 맞는다." 재 보니 맞는 칸이 0.047초(약 3장)만 보였다. 맞는 칸을 잠깐 붙잡아 두는 공통 규칙(`hold`)을 넣어 약 0.1초로, 1타 0.5초·2타 0.46초로 늘렸다. 1타 동작을 칸을 늘려 다시 보니 중간에 칼을 다시 치켜드는 동작이 섞여 있어 찌르기까지만 잘랐다. 그림이 맞는 칸을 지나가면 찌르기 잔상은 지우고 베기 호는 흐리게 남긴다.
- **반격 돌진:** 피하고 나면 대시로 멀어져 반격이 어렵다는 의견 → 세 방안 중 "반격 돌진" 선택. 반격 시간에 누르면 피한 적에게 최대 2m 파고들며 벤다(반투명 잔상). 점검: 70px 떨어진 곳에서 눌러 26px까지 붙은 뒤 피해 2배.
- **1타를 다시 가로 베기로:** 사용자 요청. 가로 베기 → 내지르기 → 올려 베기. 내지르기는 이미 잘 보이게 고친 뒤라 2타여도 괜찮다.
- **이동 속도와 뛰기:** 전투 박자에 비해 느리다는 의견으로 걷기 2.0·은신 1.3m/s, 뛰기 4.8m/s를 넣었다. 뛰기는 Space를 누른 채 이동(누르는 순간 대시, 계속 누르면 뛰기). 동작 팩의 조깅·질주 속도를 재 보니 조깅 5.87, 질주 8.28m/s라 조깅을 골랐다.
- **연타 구성 변경:** "가로 베기 → 올려 베기 → 내려치기"로. 내려치기 후보 4개를 그려 비교해 `Sword_Attack`을 골랐다. 올려 베기를 2타로 옮기자 칼이 뒤-아래에서 앞까지 약 185° 돌아 검로가 머리 위로 잘못 그려졌다 → 베기 검로는 몸 앞을 지나는 쪽으로 돌게 고쳤다(공통 규칙).
- **3타 손맛:** "3번 동작이 쥬시하지 않다." 재 보니 준비 칸들이 모두 0.1초로 똑같아 "버텼다가 확"이 없었고, 맞는 칸이 칼이 수평인 칸이었다. 머리 위에서 0.18초 버티고 0.03초 만에 땅까지 내려치게 칸 시간 비율(`windup`)을 넣고, 맞기 직전 22px 파고들기(`step`), 2칸 전부터 이어지는 검로(`trail_from`), 무게에 따라 커지는 타격 별(`burst`)을 더했다. 모두 다른 무기·적에도 쓰는 공통 규칙.

## 2026-11-13 — 제작 도구·참고 자료 조사
- 무료 제작 도구(효과음 ChipTone·jsfxr·Kenney, 한글 도트 글꼴 Galmuri, 팔레트 Lospec, 도트 편집기 Pixelorama)와 참고 자료(Dead Cells의 3D → 2D 제작 방식 — 우리 방식과 같은 생각, 손맛 강연 2편, Sakurai 히트스톱 영상, Mark of the Ninja·Darkwood의 시야·은신 설계)를 [제작 도구와 참고 자료](research/PRODUCTION_REFERENCES.md)에 정리했다. 적용 제안: 타격마다 효과음, 한글 도트 글꼴, 은신 들킴 거리 원 표시, 팔레트 통일.
- 조사한 자료로 Claude가 직접 할 수 있는 작업 18개를 [작업 목록](research/REFERENCE_WORK_LIST.md)으로 정리했다. 추천 순서: 효과음 합성·타격별 소리 → 맞으면 흰색 번쩍 → 한글 도트 글꼴 → 들키는 거리 원.
- **완성 스프라이트 조사:** 들개 후보로 무료 늑대 시트(대기·달리기·공격·피격·쓰러짐, 생성형 AI 미사용), 베기 타격 이펙트 100종, 피 튀김 이펙트를 찾았다. 좀비·사람 완성 팩은 대부분 유료이거나 32px라 크기·화풍이 달라, 사람·좀비는 같은 Blender 도구로 만드는 쪽을 추천. [외부 도구 5-7절](research/EXTERNAL_TOOLS.md).
- **제작 사이트를 직접 쓸 수 있는지:** Claude에게 맞는 건 재료를 주는 사이트(Mixamo 동작, Lospec 색, GitHub 글꼴, CC0 소리)이고, 손으로 그리는 사이트(Piskel)나 귀로 고르는 사이트(ChipTone)는 코드로 대신하는 게 낫다. LPC 생성기는 4방향 RPG 화풍·CC-BY-SA라, AI 도트 생성기(PixelLab)는 유료·생성형 AI라 제외. 다음 후보: Mixamo에서 개·늑대 동작 찾기.
- **적 콘셉트:** 사용자 아이디어 "방사능 수치를 넘으면 사람은 죽고, 그게 괴물이 된다." 피폭체는 원래 사람이었다는 설정으로 정리하고, 변이 단계를 적 종류(일반·돌진·덩치·방사)와 피폭견에 연결했다. PRD 12장에 기록.
- **피폭체 시안 1:** 콘셉트대로 "막 변한 직장인"을 주인공과 같은 방식(기본 몸 + 동작 팩의 좀비 동작 + 2D로 그린 옷)으로 만들었다. 2D 옷 그리기 도구를 의상 파일에서 색·세부를 읽게 일반화해 다른 사람·적도 같은 도구로 만들 수 있다. 상처가 처음엔 십자 모양으로 읽혀 비대칭 모양으로 고치고, 그림 점검표에 "작은 무늬는 비대칭으로"를 더했다.
- **주인공 전투 방향 논의(미확정):** 피폭 게이지 + 변이 기술, 마체테는 평소 무기·변이 기술은 빛나는 맨손 안을 제안. 이어서 사이트별로 할 수 있는 작업 16곳을 나열했다(Quaternius 동물 팩으로 피폭견 제작 가능성, Rokoko 무료 격투 동작).
- **3타 교체:** "3번째 동작이 1·2번과 흐름이 안 맞는다." 후보를 그려 비교해 보니 동작 팩에 `Sword_Regular_Combo`라는 3연타가 있고, 그 앞 두 타가 우리 1·2타와 같은 동작이었다. 그 마지막 타(칼을 든 자세에서 머리 위로 → 파고들며 내려치기)를 3타로 바꿨다. 다른 팩(첫 번째 팩)의 `Sword_Attack`이 화풍이 달라 어긋났던 것.
- 3타 후보 6개를 비교해 보여 드렸고, 지금 동작을 유지하되 "앞으로 이동은 안 해도 된다"는 의견으로 3타의 파고들기를 없앴다.
- **전투 집중 결정:** 은신의 의미가 약하다는 점(적 한 마리, 싸움에 대가 없음, 들키는 범위·시야 방향 없음)을 확인하고, 사용자가 은신을 살리기보다 **전투에 집중**하기로 했다. 방향이 B(변이된 몸의 손맛) 쪽으로 옮겨졌다.
- **조작 변경:** Shift 달리기, Ctrl 은신, Space는 대시만. 은신을 지우지 않고 키만 옮겼다.
- **우클릭 차징 + 피폭 게이지(기획 중):** 우클릭을 누르고 있으면 차징, 게이지(=피폭 수치)가 오를수록 세지지만 시야가 흐려지는 등 디버프. 게이지 규칙은 정했고 차징 중 동작을 함께 정하는 중. 코드는 아직 바꾸지 않았다.
- **변이 가속 1단계:** 우클릭을 누르는 동안 세상 10%, 주인공 1.3배. 그동안 벤 공격은 적 몸에 초록 베인 자국으로 쌓이고, 떼면 하나씩 빠르게 터진다. 피폭 수치가 오르고 단계에 따라 터지는 피해가 커진다. 게임 시간을 "세상"과 "주인공" 두 개로 나눠서 적·이펙트는 손대지 않고 느려지게 했다. 자동 점검: 시간 비율, 가속 중 피해 없음, 3연격 저장, 해제 시 합계 피해, 100% 한계 처리.
