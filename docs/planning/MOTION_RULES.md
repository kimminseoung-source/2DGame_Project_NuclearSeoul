# 동작 제작 기준 (MOTION RULES)

작성 2026-11-19. 사용자: "이거를 md 기준으로 만들어서 지키죠". 근거 조사: [MOTION_FEW_SPRITES_2026-11-19.md](MOTION_FEW_SPRITES_2026-11-19.md).
**캐릭터 동작(주인공, 피폭체, 군인, 시민, 변이)을 새로 만들거나 고칠 때는 이 문서를 먼저 보고, 끝나면 맨 아래 점검표를 통과시킨다.** 바꿀 때는 이 문서를 먼저 고치고 DESIGN_LOCK에 한 줄 남긴다.

## 1. 원칙: 그림은 적게, 움직임은 효과와 코드로

그림(스프라이트)을 늘리는 대신 아래 기법으로 동작을 만든다. PixelLab 무료분이 끝나도, 무기와 변이가 늘어도 그림 수가 거의 늘지 않게 하려는 것이다.

## 2. 기법별 규칙

| # | 기법 | 규칙 | 지금 | 코드 |
|---|---|---|---|---|
| 1 | **핵심 자세만** | 공격 하나 = 몸 그림 **3장**(준비, 치기, 회복) (2026-11-20, 3D 주인공부터. 사용자 "장수가 적을수록 세 보인다 → 네"). `keyframes.json`에 `recover`가 없으면 예전처럼 2장 후 서 있기. 생성기가 여러 장을 주면 3장만 골라 쓴다 | 적용 (hero_3d 5방향, PixelLab은 2장) | `keyframes.json`, `DirLook.key_pose` |
| 2 | **효과로 가리기** | 준비 → 치기 사이의 팔 움직임은 그리지 않고 베기 궤적 그림이 덮는다. 궤적은 앞으로 휘두를 때만, 맞는 순간에 | 적용 | `slash_fx.SpriteFx("slash")` |
| 3 | **친 자세 붙잡기 + 타격 효과** | 맞은 뒤 치기 그림을 `HIT_HOLD`(0.3) 동안 붙잡고, 히트스톱·흔들림·하얀 번쩍임·타격 효과를 같이 쓴다 | 적용 | `DirLook.HIT_HOLD`, `play.jolt`, `SpriteFx("hit")` |
| 4 | **준비 자세를 보이게** | 맞기 전까지 준비 그림을 붙잡는다(무기는 뒤로 젖힘). 준비 없이 바로 치는 그림은 쓰지 않는다 | 적용 | `keyframes.json` windup |

| 7 | **무기는 따로 (레이어)** | 몸은 빈손으로 받고, 무기는 작은 그림 한 장을 손 위치에 붙여 그린다. 손은 몸 그림에 남긴다(캐릭터 모습을 지키려고) | 적용 | `hands.json`, `find_hands.py`, `draw_weapon` |
| 9 | **양손 휘두르기** | 내려치기·휘두르기(chop)는 양손으로 잡는다: 왼손이 오른손 바로 아래 손잡이(3px)를 잡게 왼팔을 IK로 계산. 사용자 "양손으로 하는 게 더 어울림"(2026-11-19) | 적용 (남동, 사이트) | `tools/animator` "양손으로 잡기" |

## 3. 하지 않는 것

- 정지 그림을 코드로 밀고·늘이고·눌러서 동작처럼 보이게 하기 (2026-11-19 "코드로 하니까 이상해", ART_FEEDBACK)
- Claude가 그림을 직접 그리기 (2026-11-19 "넌 드로잉하지 마라"). 그림은 PixelLab·무료 에셋·사용자. Claude는 고르기, 지우기 정리(`erase_box.py`), 손 위치, 코드, 비교
- 생성 그림에 같이 그려진 효과(흰 번쩍임 등)를 그대로 쓰기. 효과는 게임이 따로 그린다. 생성할 때 `no effects, no impact flash, no particles`를 넣고, 남아 있으면 `erase_box.py`로 지운다
- 유료 사용 (PixelLab 무료분만, 동시 생성 제한 안내의 업그레이드는 누르지 않는다)

## 5-1. 3D 주인공의 새 동작 만드는 순서 (2026-11-20부터)

1. 계획서를 먼저 쓴다(`docs/plans/`).
2. Mixamo에서 동작을 받는다(FBX, 피부 없이, 30fps → `assets/source3d/mixamo/`, 저장소에 올리지 않음).
3. 큰 3D와 36px로 10장 뽑아 비교하고(`tools/blender/mpfb_pose.py`), 사용자와 고른다.
4. `tools/sprites/build_hero3d.py`의 ACTIONS에 넣고 핵심 자세 번호를 정해 `assets/characters/hero_3d`를 만든다(손 위치·무기 각도는 Blender에서 잰다).
5. `BUSAN_HERO=hero_3d`, 테스트 맵에서 숨긴 창으로 찍어 보여 준다.

## 5. 새 동작을 만드는 순서 (PixelLab, 예전)

1. PixelLab(무료) 직접 설명 동작, 방향당 1회. 설명에 "빈손, 효과 없음". 받은 파일은 `assets/characters/pixellab_downloads/<캐릭터>/<동작>/<방향>/`에 모은다.
2. 준비·치기 2장을 고르고, 남은 효과는 `erase_box.py`로 지워 게임 폴더(예: `hero_px40/Strike/<방향>/`)에 넣는다.
3. `keyframes.json`에 장면마다 그림 번호·손 위치·무기 각도를 적는다.
4. 숨긴 창으로 게임 안에서 찍어(`check_keypose`), 지금 것과 나란히 보여 준다.
5. 사람이 직접 볼 때는 **빈 테스트 맵**: `$env:BUSAN_AREA='arena'; .venv\Scripts\python.exe src\main.py` (건물·차·사람·새 피폭체 없음, 멈춘 피폭체 5마리, 발밑에 무기 5종).

## 6. 보여 주기 전 점검표

- [ ] 몸 그림이 공격당 2장(준비, 치기)인가, 회복은 서 있기로 돌아가는가
- [ ] 생성 그림에 효과가 남아 있지 않은가(흰 번쩍임, 불꽃, 먼지)
- [ ] 준비 자세가 맞기 전까지 보이는가
- [ ] 맞는 순간 궤적·타격 효과·히트스톱이 같이 나오는가, 궤적이 겨눈 쪽으로 휘는가
- [ ] 무기 손잡이가 손 위치와 맞는가(F1 빨간 점), 등을 보일 때 무기가 몸 뒤인가
- [ ] 다른 방향·다른 무기에서도 같은 규칙으로 되는가(공용 코드)
- [ ] 게임 화면(낮·밤)에서 찍어 지금 것과 나란히 비교했는가
