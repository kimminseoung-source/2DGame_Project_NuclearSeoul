# 좀보이드 분석 후 「부산까지」에 적용 (탑뷰)

사용자 요청(2026-11-14): Project Zomboid의 동작과 시스템을 분석하고, 확인한 동작부터 「부산까지」의 Python·Pico2D 탑뷰 시험판(`src/proto_top.py`)에 비슷하게 구현해 실제 게임에서 비교한다. 조사 범위는 이동과 전투, 적의 반응, 캐릭터와 애니메이션, 그래픽과 화풍.

**바뀐 점 (처음 쓴 판과 다른 것)**
- 시점: 횡스크롤 → **탑뷰** (DESIGN_LOCK 2026-11-14, "사방에서 오는 긴장감"). 배낭은 뺐다.
- 조사 방법: REA(프로그램 역분석 도구)로 하려 했으나, 이 컴퓨터에 좀보이드를 설치할 수 없어 분석할 대상이 없다. 또 REA가 밝힌 지원 대상에 Java(좀보이드의 언어)가 없다. → **공개 자료(공식 개발 글, 위키·설정 문서, 플레이 영상)로 조사**한다. Node.js는 설치했고, REA는 설치하지 않았다.
- 순서: 기획 고정 문서 규칙 6(그림보다 재미 먼저)에 따라 **적의 반응과 전투 규칙을 먼저**, 캐릭터 동작(대기 → 걷기 → 정지, 8방향)은 전투가 재밌다고 확인된 뒤.
- 좀보이드의 코드·그림·소리는 가져오지 않는다. 규칙과 느낌만 참고하고, 구현과 에셋은 모두 우리 것으로 만든다.

## 1. 기록 방법

조사 결과는 세 가지로 나눈다.
- **확인한 사실:** 공식 개발 글이나 게임 설정 문서에 적힌 것. 출처와 해당 빌드를 붙인다.
- **영상·커뮤니티에서 추정한 것:** 플레이 영상에서 보이는 것, 커뮤니티 글. 숫자는 근사치로 표시한다.
- **확인하지 못한 것:** 공개 자료에 없는 것 (정확한 공식, 내부 수치).

## 2. 적의 반응 (먼저 적용)

### 확인한 사실
| 내용 | 근거 |
|---|---|
| 좀비의 **시력(Sight)·청력(Hearing)·기억력(Memory)**은 각각 따로 정하는 값이다(예: 아주 좋음 / 보통 / 나쁨 / 무작위). 즉 좀비는 **보거나 듣고** 플레이어를 찾고, 놓친 뒤에도 **잠시 기억**한다 | 게임 설정 "ZombieLore" 항목 (Build 42 설정 정리: [PinDrop](https://pindrop.gg/project-zomboid/sandbox-settings), [Supercraft](https://supercraft.host/wiki/project-zomboid/all-sandbox-settings/)) |
| 울타리나 창문을 넘은 직후 가까이 있으면 **덮쳐 오는(lunge) 경우**가 있다 (설정 ZombiesFenceLunge, 기본 켜짐) | 같은 설정 문서 |
| 좀비가 **옆에서, 특히 뒤에서** 오면 플레이어를 붙잡을 확률이 훨씬 크고, **여러 마리가 한꺼번에** 붙으면 물릴 확률이 마리마다 더 오른다. 밀치기로 넘어뜨릴 확률은 힘에 따라 달라진다 | [공식 개발 글](https://projectzomboid.com/blog/?p=7205) |

### 영상·커뮤니티에서 추정한 것
- 발소리는 대략 8~12칸 거리까지 들리고, 경계 상태에서는 듣는 거리가 늘어난다(근사치) — [스텔스 가이드](https://projectzomboid.wiki/guides/stealth-mechanics/)
- 밀쳐서 옆이나 뒤로 돌아간 뒤 칼로 한 번에 끝내는 플레이가 흔하다 — 스팀 토론(일화)

### 확인하지 못한 것
- 뒤에서 공격할 때 물리는 정확한 확률, 넘어뜨리기 공식, 시야 각도 숫자

## 3. 우리 게임에 적용할 것 (항목별)

| # | 좀보이드에서 확인한 동작 | 지금 우리 시험판 | 바꿀 내용 | 재현 방법 |
|---|---|---|---|---|
| 1 | 보거나 들어야 찾는다, 놓쳐도 잠시 기억 | 300px 안에 들어오면 무조건 쫓아옴 | 피폭체도 **보는 방향 + 소리**로 찾고, 놓치면 마지막 위치로 간다 | 피폭체에 시야(앞쪽 원뿔)와 듣기 거리. 베기·달리기·구르기가 소리를 내고, 소리 난 곳으로 모인다 |
| 2 | 옆·뒤에서 오면 훨씬 위험 | 어느 방향이든 같은 예고(0.5초 "!") | **보이지 않는 쪽(시야 밖)에서 오는 공격은 예고가 짧다** | 피폭체가 주인공 시야 원뿔 밖에 있으면 예고 시간 단축. 바라보는 방향 시야와 맞물려 "사방에서 오는 긴장감"을 키운다 |
| 3 | 여러 마리가 붙으면 더 위험 | 마리마다 따로 공격 | 붙은 마리 수만큼 위험이 커진다 | 2마리 이상 붙으면 예고가 짧아지거나 붙잡혀 잠깐 못 움직임 |
| 4 | 창문·울타리를 넘은 뒤 덮침 | 없음 | 나중에 (건물·창문이 생긴 뒤) | — |

첫 적용은 **1번(보고 듣고 찾기)과 2번(시야 밖 공격은 예고가 짧음)**으로 하고, 적용 전후를 같은 구역에서 비교한다.

### 첫 적용 결과 (2026-11-14, `src/proto_top.py`, F2로 전후 전환)
수치는 우리가 정한 것(좀보이드 수치 아님): 피폭체 시야 260px·앞 126도·폐차에 가림, 아주 가까우면(36px) 방향 상관없이 알아챔, 소리 거리 발소리 70 / 구르기 140 / 베기 230px, 기억 3초, 시야 밖 공격 예고 0.25초(보이는 쪽 0.5초).

| 상황 | 예전 규칙 | 새 규칙 |
|---|---|---|
| 등 돌린 피폭체 150px 뒤에 가만히 2초 | 알아채고 공격 예고까지 | 못 알아챔(서 있음) |
| 같은 자리에서 허공 베기 | 쫓아옴 | 소리 듣고 돌아봐서 쫓아옴 |
| 바라보는 쪽에서 붙어 공격 | 예고 0.5초 | 0.5초 |
| 등 뒤에서 붙어 공격 | 예고 0.5초 | **0.25초** |

놓친 뒤에는 마지막으로 보거나 들은 곳으로 가며 머리 위에 "?"가 뜬다(보일 때만).

사용자가 F2로 직접 비교하고 **"새 규칙"**을 골랐다(2026-11-14). DESIGN_LOCK 2절에 확정으로 옮김.

## 4. 영상 참고 방법

Claude는 영상을 재생해서 볼 수 없다. 대신 브라우저에서 원하는 시점의 화면을 멈춰 캡처하고 분석할 수 있다. 영상에서 얻은 것은 모두 "영상에서 추정한 것"으로 기록한다.
- 사용자가 영상 링크와 볼 시점(예: 3:20 좀비가 뒤에서 붙잡는 장면)을 알려 주면 그 화면을 캡처해 분석한다.
- 움직임(동작 전환, 걷는 박자)은 사용자가 보고 한 줄로 설명해 주면 함께 기록한다.
