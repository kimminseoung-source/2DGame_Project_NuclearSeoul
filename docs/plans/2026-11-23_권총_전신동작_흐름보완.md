# 권총 전신 동작 흐름 보완

## 2026-11-23 · 사용자 플레이 후 발동작 재조사

사용자: 왼발·오른발 스프라이트가 있어도 현재 발동작은 부자연스럽다. 개선 방법을 먼저 찾는다. 이번은 조사·방향 정리이며 아래 개선은 아직 게임에 적용하지 않았다.

### 현재 코드/원화에서 확인한 문제

- `tools/pistol_flow_look.py`는 일반/조준 이동 각각 4장을 `int(phase*4)`로 선택한다. 실제 이동거리로 phase를 진행하는 것은 이미 적용되어 있으므로 이를 새 해결책처럼 제시하지 않는다. 현재 cycle distance 52/40은 원화의 접지 궤적에서 검증한 값이 아니다.
- 접지 후보 프레임을 유지하는 동안 몸은 계속 이동한다. `foot_audit.json`의 수동 추정 부츠 중심 검사에서 최대 6.519 canvas px 이동이 남았다. 이 값은 완전한 좌우 발 추적이나 전체 접지 구간 검증이 아니라 후보 구간의 기존 측정이다. 같은 바닥선/피벗은 떨림을 줄이지만 발을 지면에 고정하지 않는다. 이산 스프라이트의 미세한 미끄러짐과 큰 보폭 불일치는 구분한다.
- 이동 중에도 `recoil` 우선순위가 높아 약 .11초 동안 전신 반동 한 장으로 바뀐다. 하체의 phase는 진행하지만 표시되는 다리는 멈추며, 이후 다른 보행 자세로 건너뛴다. 걷기 그림을 늘려도 이 문제는 남는다.
- 생성 원본 `generated_walk_8.png`를 재검토했다. 접촉/통과 자세는 있으나 네 장에서 좌우 다리의 정체성과 체중 이동을 추적·검증한 자료가 없다. 프롬프트의 좌우 교대 지시만으로 성공했다고 판단하면 안 된다. 같은 발만 반복한다고 확정할 근거도 부족하다.
- 후진은 phase를 역재생한다. 방향 전환 시 발 접지/발목 구름을 재현하는 전용 후진과 같지 않다. 상하 이동도 측면 원화라 별도 한계가 있다.

### 조사 근거와 적용 판단

1. [SLYNYRD Pixelblog 50 — Human Walk Cycle](https://www.slynyrd.com/blog/2024/5/24/pixelblog-50-human-walk-cycle): 실제 보행 참고를 한 주기로 줄이고, 색으로 구분한 단순 인체를 먼저 만든 뒤 의상을 입힌다. 4/6/8장 비교가 있으며 8장은 세부 단계를 담고 6장은 절충안이다. 우리 캐릭터에는 먼저 좌우를 색으로 구분한 8단계 검증을 추천한다. 장수가 자연스러움을 보장하지는 않는다.
2. [SLYNYRD Pixelblog 60 — Side View Run 'N Gun](https://www.slynyrd.com/blog/2026/1/26/side-view-run-n-gun): 기본 보행을 만든 다음 총 든 팔을 적용하며 어깨 위치와 몸의 들썩임을 따른다. 이동 사격은 하체가 계속 재생되도록 상하체를 분리한다. 현재 B의 서로 다른 그림을 허리에서 이어붙이는 방식으로 돌아가는 뜻이 아니다. 같은 보행 원형의 phase별 연결 위치를 가진 상체가 필요하다. 자료는 측면 게임 예시이므로 우리 탑다운 방향별 처리는 추가 검증이 필요하다.
3. [Unity 공식 Scripting Root Motion](https://docs.unity3d.com/Manual/ScriptingRootMotion.html): 반복 시작/끝을 확인하고 애니메이션의 속도 곡선과 이동을 연결한다. 엔진 기능을 pico2d에 그대로 설치할 수 있다는 뜻이 아니라, 이동거리와 보행 궤적의 관계를 맞추는 원리를 참고한다.

### 다음 작은 시험의 권장 순서

1. 범위는 오른쪽 일반 걷기 한 주기부터. 정지 조준 A의 넓은 자세는 유지하되 정지 발 모양을 이동 전체에 고정하지 않는다.
2. 기존 MPFB + Walking.fbx의 실제 좌우 무릎·발목·발끝을 기준으로 접촉/체중 받기/통과/들기를 양발에 걸쳐 8단계로 선정한다. 현재 `pose_joints.json` 6장과 exporter는 재사용 가능하지만 8장 접지/단계 선정은 아직 미실행이다. 단순 균등 샘플이 좋은 키프레임이라는 보장은 없다.
3. 3D는 자세 참고로만 쓴다. 좌우 다리를 서로 다른 색으로 표시한 모형을 정지 재생과 바닥 격자 위 이동에서 모두 검수한다. 지지 발의 뒤로 가는 거리, 반대 발의 들어올림, 무릎 겹침, 골반 높이, 끝→처음 연결을 본다. 발목뿐 아니라 뒤꿈치→발끝 구름도 고려한다.
4. 검수한 모형/기준 캐릭터로 AI 원화를 제작한다. 무릎·발의 좌우 식별과 가림 순서를 원형과 대조하고, 틀린 장만 다시 만든다. 픽셀 후보정은 연결/윤곽 정리에 쓰며 작은 부위를 회전하거나 전신 평행이동으로 걷기를 대신하지 않는다.
5. 보행 원화의 지지 발 상대 이동량을 실제 게임 이동거리와 맞춰 cycle distance를 측정·조정한다. 실제 이동거리 기반 phase는 유지한다. 프레임 수만 늘리거나 fps만 높이지 않는다. 36px에서는 보이는 수준의 미끄러짐 감소와 읽히는 교대를 목표로 하며 완전한 연속 IK 접지를 약속하지 않는다.
6. 기본 걷기가 통과하면 같은 골반/어깨 기준으로 조준 보행을 만들고 이동 중 발사 반동은 상체/총에서 처리해 하체 phase 표시를 유지한다. 상체 합성이 맞지 않으면 phase별 전신 반동 그림을 대안으로 비교한다.
7. 실제 플레이에서 일반/조준 걷기, 이동 사격, 멈춤, 재출발, 반전, 벽에 막힘을 비교한다. 좌우 발 세계 좌표 기록은 직접 표시한 동일 발/접지 구간을 기준으로 보완하고, 수치 검사와 시각 평가를 모두 남긴다. 통과 후 다른 방향·구르기 등으로 확장한다.

보류: 전체 시트 무작위 재생성, AI 프레임 보간을 기본 해결책으로 삼기, 기존 36px 파츠 회전 재도입, 먼지/흔들림으로 발 미끄러짐 가리기. 현재 병목은 도구 추가보다 보행 원형과 검수 순서다.

- 사용자: 전체 동작이 어색하지 않도록 제작자가 판단하며 다듬는다.
- 유지: A의 힘 있는 정지 조준, 승인된 AI 외형. 기존 B의 고정 상체+다른 원화 하체 합성은 최종 기준에서 제외한다.
