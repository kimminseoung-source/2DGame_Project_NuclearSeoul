# 정지·이동 얼굴 일관성과 실행 버전 식별

사용자: 정지/이동 얼굴 크기가 다르다. 가장 중요한 일관성이 지켜지지 않았다. 실제 수정 동작을 보고 있는지도 확인 요청.

## 원인과 근거

- 기존 캐릭터 제작 기준/동작 상태/ANIMATION_GUIDES/MOTION_RULES/MOTION_FEW_SPRITES/ART_FEEDBACK를 읽었다. 기존의 같은 배율/몸 높이/상체 보존 검사는 다른 원화 사이의 얼굴 일관성을 검증하지 못했다.
- 코드에서 D는 C의 정지 상태8키와 D의 이동16키를 함께 사용한다. `identity_audit/before_head_comparison.png`로 실제64px 칸을 같은 배율로 비교했을 때 머리/얼굴 모양과 목 기준이 다르다. 서로 다른 생성 결과를 혼합한 것이 원인이다.
- 마지막 수정판 로그에는 UI 텍스트 캐시가601개에서 현재 항목까지 삭제하여 KeyError로 종료한 기록이 있다. 시작 직후 창이 응답한 것과 현재 사용자가 보고 있는 버전은 다르므로 단정하지 않는다.

## 적용 방식

1. 새 AI 얼굴을 생성하지 않고 승인된 D 걷기0번에서 머리/얼굴 RGBA 픽셀을 분리한다. 같은 방향의 정지·조준·반동·피격과 이동은 **한 장을 공유**한다. 목 기준 위치만 바꾸며 확대/축소/회전하지 않는다. 기존 자르기/레이어 후처리 방식으로 합성하고 목/어깨 연결을 시각 확인한다.
2. 생성 결과를 원본과 별개 `hero_pistol_gait_v4/identity/`에 저장한다. 원본/다리 보완 버전 보존. D 수정 전/후 F10도 같은 머리를 공유해 이번 얼굴 일관성이 되돌아가지 않도록 한다. 다른 각도의 넘어짐/누움은 범위 밖으로 명시한다.
3. D 로더를 실제 새 자산에 연결하고 모든 비교 창에 `FACE-R1` 표식을 고정 표시한다. F8은 과거 A/B/C 비교이며 D가 최신임을 명확히 한다. 버전과 모드/무릎 보완 여부를 구분한다.
4. `src/pixel_ui.py`의 캐시를 새 항목 삽입 전에 정리해 경계에서도 현재 텍스처가 남도록 한다. 601개 이상의 서로 다른 텍스트를 실제 SDL 경로로 생성해 종료 오류 재발을 검사한다.

## 검수

- 각 정방향 키의 머리 픽셀을 같은 목 기준으로 되돌려 SHA/바이트 대조. 원본을 다시 생성하거나 전체 몸을 키우지 않았는지 확인.
- 정지/걷기/정지 조준/조준 걷기/반동/피격 같은 크기 비교와 게임 전환 캡처. 기존 다리 보완/발소리/이동 사격 검사도 유지한다.
- 새 창의 FACE-R1/모드D/수정 후 표식을 실제 렌더에서 확인한다. 실행 직후 프로세스 응답만으로 사용자 화면을 확인했다고 하지 않는다.

## 결과

- D 걷기0번에서 동일10×9 머리 RGBA 레이어를 분리해 정방향26키(상태6+보행16+무릎 보완4)에 목 위치만 바꾸어 합성했다. 실제 D 로더의 F10 두 경로에 연결했다. 원본과32행 이하의 몸/다리, 목 옆 조준 팔을 보존했다. 새 얼굴 생성/크기 맞춤 재샘플링 없이 같은 픽셀 공유다.
- 실제 자산의 머리 바이트/SHA, 로더 파일 선택, 실제 게임 정지/이동/조준 전환, 화면 FACE-R1 표식을 확인했다.650개 실제 SDL 텍스트 생성 후 캐시가600개로 유지되고 최신 텍스처/게임 그리기가 성공하여 기존601개 종료 경계를 재현·검증했다.
- D 실명중/탄약/보행 검사와 무릎 보완/접지·음향/F10 검사 통과. C 원본은 보존하며 과거 비교로 표시한다. 다른 각도의 넘어짐/누움은 별도 원화로 남아 있으므로 전체 방향·모든 상태 완전 일관성 완료라고 하지 않는다.
- [적용 결과와 실제 비교](../../assets/characters/previews/hero_pistol_gait_v4/identity/README.md). 이전 창은 버전 식별자가 없었으므로 사용자가 어느 창을 보고 있었는지 단정하지 않는다. 새 실행은 우상단 `BUILD FACE-R1 · D 얼굴 공유`로 확인한다.
