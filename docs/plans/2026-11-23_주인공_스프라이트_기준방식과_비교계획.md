# 주인공 스프라이트 — 기준 방식부터 제작하고 결과로 비교

- 날짜: 2026-11-23
- 사용자 지시: AI 게임 오픈소스 자료를 검토해 활용을 정리하고, 우선 기준 방식으로 진행하되 다른 방식의 결과가 더 좋으면 전환한다.
- 기준: 기존 `MOTION_RULES.md`와 현재 구현의 **3D 모델·동작 → 도트 렌더**. 앞선 자료 조사에서 제안한 직접 2D 생성 시험은 비교 경로이며, 기준 제작을 대체하도록 확정하지 않는다.
- 상태: 첫 3D 제작 검토 후 사용자 교정으로 **외형 재설계 단계**. 기존 모델의 옷·자세 수정이 아니라 다른 인상과 실루엣을 원함. 새 외형 선택 전 기존 모델의 검 베기·8방향 확장은 진행하지 않는다.

## 외형과 제작 범위

- 기준 콘셉트: `assets/characters/concepts/hero_codex_v1/hero_concept_v4_sword.png`.
- 유지: 황토색 재킷, 성인 생존자, 어두운 바지, 작은 배낭, 두루마리 없음, 검.
- 장검의 세부 형태·최종 비율은 제작 제안이므로 작은 실제 화면과 함께 판단. 게임의 총·근접 비중이나 무기 수치는 이번 작업으로 바꾸지 않는다.
- 기존 MPFB 모델은 예전 체형·옷이므로 새 콘셉트의 완성 모델이 아니다. 기존 모델 렌더를 새 주인공 완성본으로 보고하지 않는다.
- 기존 게임과 원본 `.blend`를 보존하고 시안·시험 출력은 별도 폴더에 둔다.

## 오픈소스 활용 결정

| 역할 | 기본 선택 | 대안·전환 조건 |
|---|---|---|
| 외형 기준 | 현재 이미지 생성 시안 | 얼굴·옷·장비 변경은 사용자 결정으로 반영 |
| 몸·동작 | 기존 MPFB2 모델/Blender 도구, 이미 보유한 동작 | 2dimg2motion으로 같은 방향·동작을 비교해 외형·손·검·시점의 일관성이 더 좋을 때 2D 생성 경로 검토 |
| 픽셀 렌더 | 기존 `mpfb_pose.py`와 `repaint.py` | PixelOE 또는 Pixel Snapper가 동일 36px에서 가독성을 개선하고 프레임 깜빡임이 없을 때 해당 후처리만 교체 |
| 효과 | 현재 베기·타격 효과 유지 | pixelfx에서 맞는 효과를 PNG로 내보내 비교. 캐릭터 본체와 별도로 적용 |
| 시트·좌표 | 기존 폴더 구조·손 좌표 JSON | sprite-gen은 투명화·정렬·시트 정리가 부족할 때만 검토. 출력은 현재 로더 규격으로 맞춤 |
| 외부 제어 | 기존 Blender CLI 스크립트 | Blender MCP는 카메라·장면 조작이 병목일 때. 설치가 곧 품질 향상을 보장하지 않음 |

Mixamo는 이미 보유한 동작의 출처이며 오픈소스 프로그램으로 분류하지 않는다. 도구 라이선스와 모델·의상·동작 파일의 이용 조건은 별도로 관리한다.

## 단계

1. 기존 모델과 남동 대기 동작으로 렌더 공정 재실행. 출력: `assets/characters/previews/hero_sword_baseline_v1/pipeline_check/`. **기존 모델 공정 점검용**.
2. 별도 3D 복사본에서 새 콘셉트의 몸·재킷·배낭·검 외형 맞추기. 큰 이미지와 약 36px 이미지로 남동 대기 한 방향부터 비교.
3. 준비·타격·회복 3개 자세를 제작하고 손·검 접점, 발 기준, 피벗과 타이밍 확인. 몸은 무기와 분리.
4. 숨긴 게임 창에서 기존 캐릭터·적과 비교. 승인된 결과만 걷기·구르기·피격·쓰러짐과 8방향으로 확장.
5. 문제가 생긴 단계에만 대안을 시험하고, 전환 이유와 비교 이미지를 기록.

## 공통 비교 기준

- 같은 남동 방향, 같은 인물 크기(우선 36px), 같은 배경·팔레트 목표·발 기준으로 비교.
- 원본 픽셀과 게임 기본 3배에서 얼굴·재킷·배낭·검 구분 확인.
- 자세가 바뀌어도 얼굴·복장·몸 비율이 유지되는지, 손이 바뀌거나 검이 사라지지 않는지 확인.
- 프레임마다 자동 크기 맞추기를 하지 않고, 발 피벗과 무기 접점을 고정.
- 정지 이미지의 예쁨뿐 아니라 애니메이션·방향 확장·제작 시간·사용량을 함께 비교.
- 생성 스킬의 검사 통과와 게임 플레이 품질 확인을 구분.

## 결과

- 새 도구 설치·모델 다운로드·유료 서비스 호출은 하지 않는다. 외부 도구를 시험할 때 필요 항목과 용량·사용량부터 기록한다.
- 실행: `.venv/Scripts/python.exe -B -X utf8 tools/sprites/build_hero3d.py --out assets/characters/previews/hero_sword_baseline_v1/pipeline_check --dirs south-east --only idle`.
- 종료 코드 0, `built idle ['south-east']`. 기존 `.blend`와 보유한 Breathing_Idle 동작으로 ID·light 렌더와 색 재칠하기가 끝났다.
- 출력은 64×64 RGBA 대기 1장·숨쉬기 2장, 손 좌표 JSON이다. 두 숨쉬기 이미지의 불투명 영역 바닥은 모두 y=55(상한 제외)로 같았다.
- **실제 인물 높이 41px**: bbox는 (26,14,40,55), (25,14,40,55). `person_px=36` 설정과 달리 기존 머리 확대·외곽선 등이 포함된 최종 불투명 높이는 41px였다. 다음 단계에서 실측 크기를 기준으로 카메라/배율을 맞추고, 설정값만으로 36px라고 보고하지 않는다.
- 이 출력은 기존 모델의 공정 확인일 뿐 새 콘셉트의 재킷·배낭·검을 구현한 결과가 아니다. 공격 폴더가 없는 부분 출력이므로 완성 캐릭터로 게임에 연결하지 않는다.
- 새 콘셉트 모델·검 동작·게임 적용은 아직 완료되지 않았다. 기존 게임 코드와 원본 모델은 이번 점검에서 변경하지 않았다.

## 2026-11-23 작업 방식 충분성 점검

사용자 요청: 현재 방식이 충분한지 실제 구현을 확인하고, 무엇을 추가하면 발전할지 판단한다. 이번 점검은 읽기·측정과 기록이며 게임 코드나 모델을 수정한 작업은 아니다.

### 판단

**3D→도트 기준 방식은 유지한다.** 모델 재사용·8방향 동작·몸과 무기 분리·적은 핵심 자세·게임 내 비교를 위한 기반은 갖췄다. 다만 새 콘셉트의 외형 제작, 출력 크기·잘림·피벗 검수, 제작 설정 재현성이 보강돼야 양산할 수 있다. 도구를 설치하는 것과 이 품질 문제를 해결하는 것을 구분한다.

### 실제 확인한 근거

| 항목 | 확인 결과 | 해석 |
|---|---|---|
| 기존 `.blend` 직접 조회 | MPFB 몸, 스웨터·카고 바지·신발·머리·눈/눈썹·뼈대 | 새 콘셉트의 재킷·배낭·검이 완성된 모델이 아니다. 좋은 시안과 실제 모델 사이 작업이 현재 가장 큰 과제 |
| 현재 공격 참조 | 기본 samurai의 8방향×준비·타격·회복 = 24개 참조 이미지 모두 존재, 가장자리 접촉 없음 | 기존 공격의 방향·파일 구성은 재사용할 기반이 있음. 이는 새 검이 두 손에 맞거나 시각 품질이 완성됐다는 검증은 아님 |
| 대기·걷기 크기 | Breath 인물 높이 38~41px, Walking 38~42px. 앞선 남동 대기 공정 점검도 41px | `person_px=36` 인수와 최종 불투명 높이를 구분해야 함. 포즈 변화 자체로 생기는 높이 차이는 자동 오류로 판정하지 않음 |
| 파일 경계 | Breath·Walking·Aim·AimStep·MP_chop·Roll_Spin·Hurt·Down 8폴더 240장 검사. Down 32장 중 14장 bbox가 좌우 또는 아래 경계에 닿음. 다른 7폴더는 접촉 0 | 쓰러짐의 잘림 위험을 우선 점검. 일부 프레임을 직접 열어 확인했으나 모든 프레임의 실제 누락 부위를 확정하려면 여유 있는 동일 배율 재렌더와 비교해야 함. MP_chop 폴더의 수치는 현재 samurai 참조 검사와 별개 |
| 발 기준 | `DirLook._load`가 프레임마다 알파 bbox 바닥을 읽고, draw가 그 값을 위치 계산에 사용 | 그림의 아래 끝과 지면 피벗은 같지 않을 수 있음. 특히 구르기·쓰러짐의 의도된 높이/이동이 유지되는지 동작으로 확인 필요. bbox가 다르다는 사실만으로 게임에서 떨린다고 단정하지 않음 |
| 무기 구조 | 별도 무기 PNG를 손 좌표에 붙여 회전하고, 방향에 따라 몸 앞·뒤로 그림 | 재사용에 유리. 긴 검은 손잡이뿐 아니라 검끝·양손 접점·원근과 몸 가림 검수가 더 필요 |
| 재현성 | `build_hero3d.py`의 Blender 실행 파일과 `.blend` 경로가 개인 PC 절대경로, 모델은 프로젝트 밖 | 현재 PC에서 공정이 돌아가는 것은 확인. 다른 환경에서도 재현하려면 제작 설정·원본 위치·버전을 묶어 기록하고 실행 인수로 전달하는 개선이 필요. 게임 실행 리소스 경로와는 별개 |

### 우선 추가할 것 — 새 설치보다 제작·검수 강화

1. **제작용 외형 사양:** 콘셉트에서 작은 화면에 남길 실루엣·몸 비율·재킷/배낭/검의 크기·색을 고정. 기존 모델을 그 사양에 맞춘 뒤 대기 한 방향부터 실제 게임 배경에서 확인한다.
2. **출력 검수 자동화:** 투명 PNG·크기·누락 파일·알파 경계 접촉·손 좌표 범위·방향별 구성·색 수를 확인하고, 바깥 경계 접촉은 경고로 보고한다. 포즈의 실제 의미와 발 접지는 GIF·게임 재생으로 사람이 확인한다. 검사 통과가 최종 품질을 보장하지 않는다.
3. **피벗·무기 기준점 명시:** 새 에셋은 공통 지면 피벗과 손잡이/보조 손/검끝 등의 기준점을 기록. 고정 카메라와 같은 픽셀 밀도로 동작 전체가 들어갈 여백을 먼저 확보한다. 프레임별 자동 확대·축소로 잘림을 가리지 않는다. 기존 로더를 즉시 교체하지 않고 새 시안에서 검증 후 결정한다.
4. **재현 가능한 제작 설정:** 콘셉트·모델/의상 사양·팔레트·카메라·원본 동작·핵심 프레임·도구 버전·출력 위치를 캐릭터 단위로 연결한다. 제작 경로는 개인 PC 하드코딩을 줄이는 방향으로 개선하되 기존 원본은 보존한다.
5. **짧은 반복 단위:** 대기 한 방향 → 검 베기 한 방향 → 남/북/옆의 가림 점검 → 8방향 확장. 비교 결과를 기록하고, 새 도구는 실패한 단계 하나만 바꾸는 데 사용한다.

### 도구 추가의 우선순위

- **PixelOE/Pixel Snapper:** 원본 외형·카메라 문제가 해결된 뒤 축소 가독성이 부족할 때 비교. 이미 잘려 없어진 부위를 복구하거나 없는 배낭을 만드는 해결책은 아님.
- **pixelfx:** 몸 동작과 타격 시점이 맞춰진 뒤 검 궤적·투사체 충돌 효과에 적용할 첫 외부 후보.
- **2dimg2motion:** 같은 주인공·같은 한 방향의 베기를 비교하는 대안. 외형·손·검 유지가 좋고 수정 비용이 적을 때 전환 검토. 기본 14장 전체를 그대로 적용하는 결정을 뜻하지 않음.
- **Blender MCP/추가 렌더 애드온:** 현재 CLI로 모델 열기·공정 실행이 가능하므로 필수 추가가 아님. 반복 장면 조작이나 미리보기 속도가 병목으로 확인될 때 검토.
- **프로젝트 전용 스킬:** 공정이 안정되면 기존 규격·실행 명령·검수·인수인계를 한 절차로 묶는 것이 유용. 실제 모델·렌더 도구를 대체하는 생성기로 보지 않으며 이번에 새 스킬을 만들거나 설치하지 않음.

이번 확인에서는 외부 프로그램·스킬 설치, 게임 코드 수정, 원본 모델 덮어쓰기, 커밋·푸시를 하지 않았다.

- 이번 완료 단위: 새 외형의 3D 복사본, 남동 대기·숨쉬기 두 프레임, 몸/검 분리 출력, 실제 크기 및 게임 배경 미리보기. 검 베기·8방향 확장은 이 결과를 확인한 다음 단계다.
- 파일: 새 제작 스크립트 `tools/blender/hero_sword_preview.py`, 제작 사양 `assets/characters/concepts/hero_codex_v1/production_v1.json`, 3D 원본 복사본 `assets/source3d/scenes/hero_sword_v1/hero_sword.blend`, 출력 `assets/characters/previews/hero_sword_model_v1/`.
- 현재 Blender에서 `addon_utils`로 MPFB 확장이 발견되지 않았다. 이미 저장된 리깅 모델을 재사용하고, 의상 메시·소품을 별도 복사본에서 수정한다. 새 애드온·모델은 다운로드하지 않는다.
- 원본 외형은 콘셉트와 차이가 있으므로 스웨터 의상을 재킷 형태로 조정하고, 어두운 안옷·어깨 보강·가슴 주머니·작은 배낭·검을 추가한다. 결과를 동일 이미지로 완벽 복제했다고 보고하지 않는다.

### 첫 제작 결과

> 후속 사용자 피드백: 기존 캐릭터와 크게 다르지 않으며 다른 모습을 원했음. 체형·자세 방향 제안은 조금 나아졌다고 했지만 외형 확정은 아님. 새 외형 비교 시안은 `assets/characters/concepts/hero_redesign_v1/hero_three_designs.png`. 기존 결과는 제작 실험으로 보존한다.

- 완료 파일과 재현 방법: `assets/characters/previews/hero_sword_model_v1/README.md`.
- 최종 모델 복사본: `assets/source3d/scenes/hero_sword_v1/hero_sword_v6.blend`.
- 몸 두 프레임 bbox `(26,17,40,53)`: 높이 36px, 발끝 동일. 검 포함 두 장도 높이 36px이며 총 4개 출력 모두 64×64 RGBA, 캔버스 가장자리 접촉 없음.
- 정사영 카메라를 첫 대기 프레임의 실제 렌더로 한 번 맞추고 고정했다. ID 패스의 그림자로 부위 색이 잘못 분류되던 문제를 수정했다.
- 몸과 검을 따로 렌더해 `hands.json`·지면/검끝 좌표를 기록했다. `held/`는 검 포함 외형 참고용이며 게임의 무기 교체 연결 완료를 의미하지 않는다.
- 게임 배경 캡처는 프로세스 내 임시 draw 교체로 확인했다. 기존 `hero_3d`, 게임 소스, 원본 .blend는 이번 작업에서 변경하지 않았다.
- 아직 재킷의 세부 형태·얼굴 표현이 원화와 다르고 검 베기·걷기·8방향·전투 판정은 미검증이다. 첫 제작을 검토한 뒤 다음 단계로 간다.
