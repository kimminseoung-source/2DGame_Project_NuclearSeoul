# 보행 기법 조사 후 실제 적용

사용자 요청: Claude의 기존 조사 MD를 먼저 활용하고, 추가 조사한 기법을 실제 적용한다. 다음 작업도 조사→적용→검수를 반복한다.

## 먼저 확인한 기존 기록

- `docs/planning/MOTION_FEW_SPRITES_2026-11-19.md`: 핵심 자세, 상하체 분리, 효과와 본체 역할. 공격용 2~3장 규칙을 보행에 적용하지 않는다.
- `docs/planning/MOTION_RULES.md`: 걷기/조준 걷기 위상, 원본 모션 활용, 이미지 변형 금지.
- `docs/references/ANIMATION_GUIDES.md`: AI 일관성, 파츠 회전/SD1.5 실패, 자세 안내와 최종 그림 구분.
- `assets/characters/ART_FEEDBACK.md`: 접지 발을 1/60초마다 검사, 실제 게임 크기 비교, 수치와 시각 검수를 구분.
- `docs/research/ZOMBOID_ANIMATION_RESEARCH.md`: 조준 방향과 이동 방향 분리, 전환 상태.

## 이번에 적용할 근거

- [SLYNYRD Human Walk Cycle](https://www.slynyrd.com/blog/2024/5/24/pixelblog-50-human-walk-cycle): 참고 동작의 8단계, 색 구분 모형, 모형 뒤 의상, 4/6/8장 비교.
- [SLYNYRD Side View Run 'N Gun](https://www.slynyrd.com/blog/2026/1/26/side-view-run-n-gun): 기본 보행 뒤 총 든 팔 적용, 이동 사격 중 하체 재생 유지. 측면 예시를 탑다운 전체 방향 해결책으로 과장하지 않는다.
- [Monmouth University Walk Cycle](https://animation.monmouth.edu/instruct/animation/walk-cycle/): 반대 발 접촉을 반 주기에 배치하고 통과/다운/밀어내기 추가. 마지막 중복 시작 프레임은 루프에 넣지 않는다.

## 적용 범위와 순서

1. 기존 원본 blend를 읽기 전용으로 열어 Walking.fbx의 실제 8시점 관절을 추출한다. 좌우 색 구분과 단계 순서를 검수한다. 보행 안내 모형은 코드로 그리되 최종 캐릭터는 AI 원화로 만든다.
2. 새 `hero_pistol_gait_v4`에 원화/안내/메타데이터/검수 결과를 보존한다. AI가 안내를 따랐는지 별도로 확인하고 같은 발 반복/접지/실루엣/크기 오류를 검수한다.
3. 기존 C는 보존하고 D 비교 모드를 추가한다. 8키 실제 이동거리 기반 보행, 사격 시 다리 표시가 멈추지 않도록 적용한다. 정지 A 조준 선호는 유지한다. 새 이동 중 전용 상체 반동 원화가 없으면 기존 총구 효과로 발사를 표시하고, 전신 반동으로 다리를 멈추지 않는다.
4. 실제 발 좌표를 표시한 원화에서 보폭을 산정한다. 60Hz 단위 발 궤적, 루프, 조준 전환, 이동 사격, 좌우 반전, 정지/재출발을 검사한다. 기술 검사 통과와 시각 품질 통과를 따로 기록한다.
5. 문서 조회가 다음 작업의 실제 시작 조건이 되도록 프로젝트 AGENTS 및 캐릭터 제작 기준에 연결한다. 적용/보류/실패 결과는 같은 자료로 돌려 기록한다.

전체 8방향, 전용 구르기/줍기, 최종 총 분리는 이번 작은 시험의 완료 범위가 아니다. 추가 도구 설치/유료 이용은 하지 않는다.

## 결과

- 적용 완료: 실제3D 관절8시점 추출 뒤 접지 순서를 분명히 한 별도 설계 안내를 만들었다. AI 출력의 반복/틀린 다리 정체성을 반려·지정 수정하고 일반/조준 전신8키씩을 `hero_pistol_gait_v4`에 저장했다. 실제 캡처와 설계 안내를 구분한다. 생성 요청/후처리/검수는 결과 README와 prompts.json에 남겼다.
- D 비교 모드 추가, 기본 D/F8 A/B/C/D, 기존 C 보존. `pistol_gait_look.py`/`pistol_flow_look.py`/`run_pistol_comparison.py`에 8키/발 표시 기반 보폭48.9375world/거리 위상/이동 사격 하체 표시 유지 적용.
- 실제 게임 검사에서 권총도 기존 근접공격 경로 때문에 입력 이동이 멈추는 추가 원인을 발견했다. `src/hero.py`의 공통 이동 처리를 함수로 추출하고 `walk_while_shooting` 기본False, D에서만True로 이동 사격을 허용했다. 피해/탄약/사격 시간은 유지하며 D 이동 중의 뒤로 밀리는 런지는 입력 이동으로 대체한다. 기본 게임/근접/C는 기존 경로다. C/D가 완전히 같은 이동 동작 비교라고 하지 않는다.
- 실제 D 검사: 일반/조준8키, 실명중·탄차감과 발사 중 하체 표시/위상, 정지/이동 차단/정지 시계, 반대쪽 조준 이동, A/B/C/D 상태 보존·초기화. C의 이동/조준/발사/피격·사망 회귀 검사도 통과했다. 게임 C/D 비교 GIF와 시트를 시각 검토했다.
- 수동 추정 부츠 중심 기준 같은 프레임 유지 중 최대 이동은 C6.519→D3.259native px. D 후보 지지 구간 전체 범위는7.654px로 남는다. 수치 감소는 완전 접지 보장이 아니다. 발 내밀기/착지 간격, 체중 이동은 추가 보완 여지가 있고 새 이동 상체 반동 그림은 아직 없다. 기존 명중 히트스톱은 세계 전체에 유지된다.
- 후속 작업의 조사 시작 조건을 루트 AGENTS/CLAUDE, CHARACTER_WORKFLOW에 명시하고 참고 모음/동작 규칙/실패 기록/동작 비교표/인수인계에 적용 결과를 연결했다.
